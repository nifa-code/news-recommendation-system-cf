# 基于协同过滤算法的个性化新闻推荐系统

## 系统采用前后端分离四层架构：

**前端层**：React + MUI 实现页面渲染、用户交互、请求发送。

**接口层**：RESTful API 提供标准化接口，完成前后端数据交互。

**业务层**：SpringBoot + SpringSecurity 实现用户认证、行为采集、新闻管理、权限控制。

**数据与算法层**：其中缓存层由 Redis 实现，负责存储热门新闻、用户行为和推荐结果，从而减少数据库查询次数，提升接口性能。MySQL 负责数据存储；Python 实现改进协同过滤、时间衰减、混合推荐与已读过滤。



## 功能模块划分
**系统分为六大核心模块**：
**用户认证模块**：注册、登录、Token 管理、权限拦截。

**新闻展示模块**：首页推荐列表、新闻详情、实时刷新。

**智能化新闻解读**： 能查询ai工具新闻要点，以及背后所涉及的一些要素分析，查询对新闻不解的方面，高效分析读取新闻，学习新的知识。

**个性化推荐模块**：改进协同过滤、时间衰减、混合推荐、冷启动、已读过滤。

**用户行为采集模块**：点击、阅读、点赞、收藏采集，防重复处理。

**个人中心模块**：用户信息、阅读统计、退出登录。

**记录管理模块**：浏览历史、收藏记录、删除 / 取消收藏。

## 跨模块交互设计：

  为实现个性化新闻推荐功能，本系统采用跨服务交互模式。

  前端用户发起推荐请求后，由 Java 后端接收请求并调用 Python 推荐服务接口；
  
  Python 服务访问 MySQL 数据库读取数据集与用户行为数据，依托协同过滤算法完成相似度计算与推荐列表生成；
  
  最终将推荐结果回传给 Java 后端，后端再查询完整新闻信息并返回前端渲染展示。


## 数据预处理流程
为适配改进协同过滤算法，对原始获取到的实验交互数据集进行如下预处理：

**1. 数据清洗**：剔除缺失用户 ID、缺失新闻 ID、无效时间戳等异常记录，保证数据完整性。

**2. 行为映射**：将原始点击行为转换为算法可识别的评分权重。

**3. 时间格式统一**：将非标准时间字符串转换为 DATETIME 格式，用于后续时间衰减计算。

**4. 时间窗口划分**：按时间戳将数据划分为训练集（前70%）、验证集（15%）和测试集（15%），用于离线评估。

**5. 构建用户‐新闻交互表**：将用户与新闻的交互记录导入系统  user_behavior 表，作为协同过滤算法的输入。

**6. 数据导入数据库**：将处理后的用户、新闻、行为数据批量导入 MySQL 数据库，供 Java 后端与 Python 算法模块调用。

采用改进的用户协同过滤算法，主要改进包括：**余弦相似度计算**、**时间衰减权重**、**混合推荐策略**、**已读过滤与冷启动机制**。

## 个性化推荐生成
**推荐流程如下**：
**1.** 判断用户是否为新用户，新用户直接进入冷启动策略（公式4-8）；

**2.** 对老用户，从相似度矩阵获取 Top‑N 相似用户；

**3.** 收集相似用户产生过行为、但当前用户未阅读过的新闻作为候选；

**4.** 按相似度、行为评分、新闻流行度综合计算推荐分数；

**5.** 过滤已读新闻（公式4-7），并执行多样性优化；

**6.** 若无有效候选，则降级返回热门新闻。

(混合推荐中的热门与最新新闻融合由 Java 后端完成。Java 服务接收到 Python 返回的协同过滤候选列表（最多50条）后，

从数据库查询热门新闻排序前30条和最新新闻前20条，按 6:3:1 的比例混合，去重并随机打乱后返回前端。)

## 开发环境与技术栈
本章对个性化新闻推荐系统进行详细设计与代码实现，基于前后端分离架构完成各模块开发。系统所用环境与技术如下：

后端：IntelliJ IDEA、SpringBoot 2.7.x、SpringSecurity、MySQL 8.0、Maven。

前端：VS Code、React 18、MUI、Axios。

算法：Python 3.x、Pandas、Numpy。

运行环境：Windows 11、JDK 1.8、Node.js。

## 后端服务实现
后端采用 Controller、Service、Mapper、Entity 四层分层架构，职责明确，易于维护。

Controller 层提供登录、注册、新闻、推荐、行为、历史、收藏接口。

Service 层实现业务逻辑、行为采集、已读过滤、权限校验。

Mapper 层完成 MySQL 数据增删改查。

安全配置使用 BCrypt 加密密码，JWT Token 实现无状态认证。
